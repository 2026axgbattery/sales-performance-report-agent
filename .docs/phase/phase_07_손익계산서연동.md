# Phase 7 작업 계획서 — 팀별 손익계산서 실제 파싱

- 근거 문서: [.docs/03_데이터정제.md](../03_데이터정제.md) §6.2 (더미 파일 실측 결과 갱신분 포함)

## 배경/동기

`손익계산서_더미데이터.xlsx`를 openpyxl로 직접 열어 재확인한 결과, 팀별 시트(모티브/고정형/대리점/차량oe)는 계정과목(행) × 월(열) 구조이고, 일부 행(매출원가(A)Tot, 매출총이익(A), 판관비(Total), 영업이익(A))은 판매계획 파일의 "금액=판가×수량"과 동일한 패턴으로 **수식이 계산되지 않은 채 저장**되어 있다(`=SUM(B8:B40)`, `=B5-B6`, `=SUM(B44:B80)`, `=B41-B42`). 지금 `team_pl_record`는 원본을 파싱하지 않고 raw_payload로만 저장하므로, 이번에 실제 계정과목 파싱과 4개 소계 항목의 직접 계산을 구현한다.

## 범위

**구현**: `team_pl_record`를 team×account_item×year×month×amount로 실제 파싱하고, 4개 소계(매출원가(A)Tot/매출총이익(A)/판관비(Total)/영업이익(A))는 캐시값을 믿지 않고 확인된 수식 그대로 직접 계산한다.

**범위 밖(이번에 하지 않음)**: F3·F4 계산 로직이 team_pl_record를 조회하도록 연결하는 것 — 현재 F3/F4 요구사항 중 이 데이터를 직접 참조해야 하는 항목이 없다(PRD F2의 "팀 단위 손익 관점의 분석도 가능하게 한다"는 서술적 목표이지 구체적 F-번호 요구사항이 아님). 저장까지만 하고, 조회·활용은 필요해지면 별도로 진행한다. `국내`(전사 집계) 시트도 파싱하지 않는다 — 팀별 시트를 합산하면 얻을 수 있는 값이라 저장 시 중복이다.

## 방법

1. `backend/app/db.py` — `team_pl_record`를 `record_id, file_id, batch_id, team, account_item, year, month, amount`로 재설계(`COLUMN_MIGRATIONS`로 로컬 DB 안전 확장).
2. `backend/app/services/team_pl.py` 신규 — 팀별 시트를 openpyxl로 파싱:
   - 헤더 행("구분" 셀 탐색)을 팀 시트마다 동적으로 찾는다(더미 파일은 팀 시트 전부 3행이지만 고정값으로 가정하지 않는다).
   - 연도는 팀 시트 자체에는 없고 `국내`(집계) 시트 제목에만 있어, `국내` 시트에서 추출해 모든 팀 시트에 공통 적용한다.
   - 계정과목 행마다 1~12월 값을 그대로 읽되, 매출원가(A)Tot/매출총이익(A)/판관비(Total)/영업이익(A) 4개 행은 실측한 수식(SUM 범위, 뺄셈)을 그대로 재현해 직접 계산한다.
3. `backend/app/routers/uploads.py` — 파일 종류가 "손익계산서"이면 `read_dataframe`(단일 시트 가정) 대신 새 파서를 호출하도록 분기(판매계획과 동일한 패턴).
4. 테스트: 축소된 실제 구조를 반영한 xlsx 픽스처로 파서 단위 테스트(소계 직접 계산 검증 포함) + 업로드 통합 테스트.

## 완료 기준

- `team_pl_record`가 팀×계정과목×월 단위로 저장된다.
- 매출원가(A)Tot/매출총이익(A)/판관비(Total)/영업이익(A) 4개 소계가 원본 캐시값이 아니라 확인된 수식으로 직접 계산되어 채워진다.
- 실제 더미 파일(4개 팀 시트 전체)로 파싱·업로드 종단 확인.
- 백엔드 pytest 전체 통과.
