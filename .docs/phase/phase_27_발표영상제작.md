# Phase 27 — 과제 발표(시연) 영상 제작

## 배경 / 동기

AX전문가과정 최종 제출물 ② "실제 작동하는 플로우가 담긴 화면 녹화 영상(2분 이내)". PPT 보고서(① )는 사용자가 이미 작성했다.
사용자 요청: "이 과제의 실제 구현을 통한 설명(발표) 동영상을 만들어줄 수 있겠어?"

- 대상 시청자: 과정 평가자(AX전문가과정). 업무 현장 용어(SAP, 이상징후 등)는 알지만 이 앱은 처음 본다.
- PPT 흐름(과제 선정 이유 → As-Is 월 12시간 → 기대효과 → 작동 방법 → 결과물)과 영상의 설명 순서를 맞춘다.

## 범위

- 포함
  - 실제 앱(Next.js + FastAPI + DuckDB)을 브라우저로 조작하는 장면을 자동 녹화(마우스 커서·클릭 표시, 하단 자막 포함)
  - 한국어 나레이션(Windows 내장 음성 Microsoft Heami)과 자막, 도입·마무리 카드(As-Is→To-Be 수치)
  - 결과물: MP4(H.264 + AAC, 1280×720, 120초 미만), 발표 대본
  - 재생성할 수 있도록 제작 스크립트를 `tools/demo-video/`에 둔다(UI가 바뀌거나 배포 주소가 확정되면 다시 만들 수 있게)
- 제외
  - PPT 수정(사용자 작성본, 읽기만 함)
  - 사용자 본인 목소리 녹음(대본을 제공하므로 원하면 교체 가능)
  - 실제 운영 데이터 사용 — 영상에는 **가상 데이터만** 나온다

## 방법

1. **격리된 데모 환경**: 로컬 실데이터 DB(`backend/data/app.duckdb`)를 쓰지 않고, 별도 DuckDB 파일을 `APP_DB_PATH`로 지정한 백엔드(:8001)와
   그 주소로 빌드한 프론트(:3100)를 띄운다(Phase 23과 같은 방식).
2. **가상 데이터 준비**: `scripts/seed_demo.py`의 `build_demo_frames()`로 만든 1~8월 가상 실적 중 1~7월은 미리 넣고(판매계획·매핑표·
   정합성을 맞춘 손익계산서 포함), **8월 실적 파일은 영상 안에서 직접 업로드**해 "업로드 → 정제·집계·판정"을 실제로 보여준다.
   (여러 달을 한 번에 올리면 목표가 비는 알려진 문제가 있어, 영상에서 올리는 8월은 단일 월 경로를 탄다.)
3. **녹화**: Playwright(Edge)의 `recordVideo`. 장면마다 나레이션 길이에 맞춰 대기해 소리와 화면을 동기화하고, 장면 시작 시각을 기록한다.
4. **음성**: PowerShell `System.Speech`로 장면별 WAV 생성 → 길이 측정 → 장면 시작 시각에 맞춰 배치.
5. **합성**: `imageio-ffmpeg`가 제공하는 ffmpeg로 영상+음성을 MP4로 합친다.
6. **검증**: 완성 MP4에서 장면별 프레임을 뽑아 화면·자막·커서를 눈으로 확인하고, 길이와 오디오 스트림을 확인한다.

## 재생성 방법 (UI가 바뀌었거나 배포 주소가 확정됐을 때)

작업 폴더(예: `%TEMP%\demo-video`)를 정하고 아래 순서로 실행한다. 실데이터 DB(`backend/data/app.duckdb`)는 절대 쓰지 않는다.

1. 음성: `powershell -File tools/demo-video/tts.ps1 -OutDir <폴더>\audio` (대본은 `tools/demo-video/narration.json`)
2. 데이터: `python tools/demo-video/prepare_demo_data.py --out <폴더>\data --make`
3. 데모 백엔드: `APP_DB_PATH=<폴더>\demo.duckdb CORS_ALLOW_ORIGINS=http://localhost:3100 uvicorn app.main:app --port 8001` (`backend/`에서) →
   `python tools/demo-video/prepare_demo_data.py --out <폴더>\data --preload --api http://127.0.0.1:8001`
4. 데모 프론트: `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8001 npm run build` 후 `npx next start -p 3100` (`frontend/`에서)
5. 녹화: `cd tools/demo-video && npm install && npx playwright-core install ffmpeg && node record.mjs --out <폴더>\work --audio <폴더>\audio --live "<폴더>\data\2026년08월_실적RawData_가상.csv"`
6. 합성: `pip install imageio-ffmpeg` 후 `python tools/demo-video/build_video.py --work <폴더>\work --audio <폴더>\audio --out <결과>.mp4`
7. 정리: 데모 서버를 끄고 `frontend`를 `npm run build`(기본 설정)로 다시 빌드해 `.next`를 원래대로 돌린다.

다시 녹화하려면 3번의 데모 DB 파일을 지우고 다시 시작해야 한다(영상 안에서 올리는 8월이 이미 들어 있으면 겹치는 달 확인창이 뜬다).

## 후속 요청 — 무음 버전에 대본 전문 자막 (2026-10-04)

사용자 요청: "무음(자막만)에 음성 버전에서의 대본을 화면 아래 자막으로 넣어주면 좋겠어. 소리 없이 자막만 읽어도 도움이 되게."

- 범위: 무음 영상의 하단 자막을 짧은 요약("① 8월 실적 업로드 …")에서 **나레이션 대본 전문**으로 교체. 음성 버전은 그대로 둔다.
  제목·As-Is/To-Be·마무리 카드 장면에도 자막을 표시한다(카드에는 요약 문구가 없고 말로만 설명하므로).
- 방법: `record.mjs`에 `--subs script` 모드를 추가한다. 장면 대본을 문장으로 나누고(긴 문장은 쉼표·공백 기준으로 한 줄 분량까지 더 쪼갬),
  글자 수 비율로 그 장면의 음성 길이에 맞춰 순서대로 표시한다. 화면 동작은 음성 버전과 동일해 장면 시작 시각이 같다.
  `build_video.py`에 `--silent` 옵션(오디오 트랙 없이 MP4 생성)을 추가한다.
- 완료 기준: 무음 MP4에 오디오 스트림이 없고, 모든 대본 문장이 겹치거나 잘리지 않고 순서대로 나온다(장면별 프레임 확인), 길이 2분 미만.
