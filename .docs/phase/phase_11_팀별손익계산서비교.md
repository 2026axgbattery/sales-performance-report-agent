# Phase 11 작업 계획서 — 팀별 손익계산서 계획 대비 실적 비교

- 근거 문서: 사용자가 제공한 네트워크 공유 원본 경로(`\\61.81.244.248\국내영업기획팀\#2. 매출손익실적\4. 손익 분석\...`)의 로컬 사본 `2026년 08월 4. 손익분석 (2단계 배포용) 1.xlsb`(프로젝트 루트) — "계획", "실적 Re-arrange", "월간손익보고" 시트 실측

## 배경/동기

사용자 요청: "손익계산서에서는 제품구분 같은 항목을 나눌 필요는 없고, (국내=팀 전체, 모티브, 고정형, 차량대리점, 차량OE)에 대한 계획 금액 대비 항목 비교만 진행하면 되는데.. 업로드 실적 자료를 데이터 정제를 한 후, 손익계산서 형태로 정리하고 비교하는거야."

첨부 스크린샷은 계정과목별(원재료비 5개 세부/주재료비 3개 세부/부재료비/포장비 등/노무비/경비/판관비 세부 20여 개/총원가/영업이익)로 **계획·실적·계획대비(단위당/총액/비중 또는 증감율)**를 나열한 표다. 실제 파일로 이 표의 계산 규칙을 역산 검증했다:

- **단위당** = 총액 ÷ 매출수량
- **비중** = 항목 총액 ÷ 매출액 총액 (계획·실적 각각 자기 매출액 기준)
- **계획대비**: 단위당·총액은 `실적 − 계획`(음수는 빨간색 표시), 증감율은 `(실적 − 계획) / 계획`

또한 실제 파일의 "계획" 시트가 **팀×월 단위로 68개 계정과목 전체**(원재료비 세부, 주재료비 세부, 부재료비, 포장비, 노무비(변동직접/고정직접/간접), 경비(고정/변동/외주가공), 원가절감 5종, 판관비 세부 20여 개, 영업이익 등)를 담고 있음을 확인했다. 이 열 목록은 기존 Phase 7에서 이미 `team_pl_record`로 파싱하기로 설계한 "손익계산서" 파일 종류(팀별 시트, 계정과목×월 구조, [.docs/03_데이터정제.md](../03_데이터정제.md) §6.2)와 계정과목 이름이 정확히 일치한다 — 즉 **"계획" 값의 출처는 F1에서 이미 지원 중인 "손익계산서" 파일 업로드(`team_pl_record`)**이고 별도 신규 업로드 슬롯이 필요 없다.

반면 **실적 쪽**은 현재 `app/services/refinement.py`가 68개 계정과목 중 매출·원재료비·주재료비·최종손익·매출수량 예외규칙 등 일부만 구현한 상태라(CLAUDE.md에 명시된 기존 한계), 이 비교표에 필요한 노무비/경비/판관비 세부 항목·원가절감 항목이 `refined_sales_record`에 없다. 이번 작업의 핵심은 이 갭을 메우는 것이다.

## 범위

**구현**:
1. `refine_row`가 산출하는 계정과목을 §4.4(노무비·경비)·§4.5(판관비)까지 확장 — Raw Data 원본 복사 패턴(패턴①)이 대부분이므로 `REQUIRED_RAW_COLUMNS`에 해당 컬럼을 추가하고 `RefinedRow`에 필드를 추가한다. 원가절감 5종(구매/광주/창원/품질/국내/해외)도 포함.
2. 팀×월 단위로 이 확장된 계정과목 전체를 합산하는 새 집계(신규 테이블 또는 서비스 함수) — 기존 `aggregated_result`(팀×제품군 단위, F3/F4용)와는 별도 축이므로 재사용하지 않고 신규로 만든다. "국내"(전체 팀 합계) 행도 함께 계산한다.
3. `team_pl_record`(이미 존재, 팀×계정과목×월×금액)를 "계획" 값으로 조회하는 비교 서비스 — 위에서 검증한 단위당/비중/계획대비/증감율 계산 규칙을 그대로 구현.
4. 새 API 엔드포인트(예: `GET /batches/{id}/pl-comparison?team=...`)로 팀 선택(국내/모티브/고정형/차량대리점/차량OE) + 해당 배치(월)에 대한 계획 대비 실적 손익계산서 표 데이터를 반환.
5. 프론트엔드는 이번 phase 범위에서 제외하거나(백엔드까지만 우선 구현 후 확인), 사용자가 원하면 후속 단계로 F4 Overview에 탭 추가.

**범위 밖(이번에 하지 않음)**:
- 제품군별/거래처별 세분화 — 사용자가 명시적으로 "제품구분 같은 항목을 나눌 필요 없다"고 확인함.
- YTD(누계) 비교 — 스크린샷은 당월 단일 시점 비교만 보여줌. 필요해지면 별도 확인 후 진행.
- "전략기획팀 회계조정액" 섹션(스크린샷 하단) — 이 값의 산출 근거(회계조정이 어디서 오는지)가 아직 미확인이라 임의로 구현하지 않는다. 필요 시 사용자에게 추가 확인.

## 방법

1. `.docs/03_데이터정제.md` §4.4·§4.5에 노무비·경비·판관비 세부 계정과목의 Raw Data 컬럼명을 실측 반영(이미 §4에 계정과목명은 문서화돼 있으나 실제 헤더 텍스트 재확인 필요 — 앞서 겪은 헤더 오탈자 패턴이 이 영역에도 있을 수 있음).
2. `backend/app/services/refinement.py`: `REQUIRED_RAW_COLUMNS` 확장, `RefinedRow`에 필드 추가, `refine_row`에서 해당 값들을 원본에서 그대로 복사.
3. `backend/app/db.py`: `refined_sales_record`에 새 컬럼 추가(`COLUMN_MIGRATIONS` 필수), 신규 팀×월 집계 테이블(가칭 `team_pl_actual_summary`) 추가.
4. `backend/app/services/aggregation.py` 또는 신규 `backend/app/services/pl_comparison.py`: 팀×월 합산 로직 + `team_pl_record` 조회 + 비교 계산.
5. `backend/app/routers/`: 신규 엔드포인트 추가.
6. 테스트: 계정과목 확장에 대한 `test_refinement.py` 케이스, 비교 계산 단위 테스트(단위당/비중/계획대비 공식 검증), 업로드~조회 종단 테스트.

## 완료 기준

- 실제 참고 파일(`2026년 08월 4. 손익분석 (2단계 배포용) 1.xlsb`)의 "계획" 시트 값과, 같은 파일의 "실적 Re-arrange" 데이터를 F1 형식으로 변환해 업로드했을 때, 새 비교 엔드포인트가 반환하는 계획·실적·계획대비 수치가 스크린샷 표와 (반올림 오차 내에서) 일치한다.
- 백엔드 전체 pytest 통과.
- 노무비/경비/판관비 세부 항목의 실제 컬럼명을 추정 없이 실측 확인했음을 `.docs/03_데이터정제.md`에 기록한다.
