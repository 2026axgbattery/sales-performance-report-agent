# 작업계획서 — 영업실적·손익 분석 및 보고서 자동 생성 Agent PRD 작성

## 1. 배경 및 동기

국내영업본부 김영우 책임이 제출한 PBL 과제개발기획서(`01_과제개발기획서_v2.md`)를 기반으로, 실제 개발에 착수할 수 있는 수준의 완전한 PRD(제품 요구사항 문서)를 작성한다. 기획서에는 As-Is 업무 방식, 정량적 효용성, 예상 작업 흐름(①~⑧단계)까지는 정의되어 있으나, 타겟 사용자 범위, MVP/이후 단계 경계, 기술 제약, 완료 기준, 이상징후 임계치 등 PRD 작성에 필요한 세부 의사결정이 비어 있어 사전 확인이 필요했다.

## 2. 사전 확인 결과 (사용자 답변)

| 항목 | 결정 사항 |
|---|---|
| 타겟 사용자/권한 | 김영우 책임 1인 전용 (업로드·분석·조회 모두 단일 사용자) |
| MVP 범위 | 업로드 → 정제 → 증감률/이상징후 계산 → Overview → 상세보고서 초안 생성까지. 배포(이메일 발송 등)는 MVP 범위 밖, 사람이 수동 처리 |
| 기술적 제약 | SAP ERP 연동은 파일 업로드 방식으로 고정 (API 연동 없음). 그 외 스택/배포 환경은 자유 제안 |
| 완료(Done) 기준 | 로컬/개인 환경에서 데모 가능한 프로토타입 (실서버 배포 불필요) |
| 이상징후 임계치 | 하드코딩된 고정값이 아닌, 앱 내 사용자가 조정 가능한 설정값으로 설계. 기본값은 PRD 작성자가 합리적으로 제안 |

## 3. 범위

- **포함**: 문제 정의, 타겟 사용자·페르소나 2개, 목표/비목표, 사용자 스토리, 기능 목록(MVP/v2/이후), MVP 상세 기능 요구사항, 데이터 모델 스케치, 엣지 케이스·실패 상태, 성공 지표, 미해결 질문
- **제외**: 실제 코드 구현, 시스템 아키텍처 상세 설계(DB 스키마 DDL 수준), UI 와이어프레임, 배포·이메일 발송 기능 상세 설계(v2 이후로 명시만)

## 4. 방법

1. `01_과제개발기획서_v2.md`의 As-Is 업무 흐름과 사용자 답변을 근거로 문제 정의 및 목표를 구체화한다.
2. 예상 작업 흐름 ①~⑧단계를 MVP(①~⑥, 사람 검토 ⑦ 제외한 자동 생성 부분까지) 기준으로 재구성한다.
3. 이상징후 판단 기준(전월/전년 대비 증감률, 계획 대비 달성률, 흑자→적자 전환, 평균단가 변동, 특이비용 급증)에 합리적 기본 임계치를 제안하고 조정 가능하도록 설계한다.
4. 매핑표는 기획서 참고사항대로 MVP에서는 입력값(파일)으로만 처리하고, 자동 학습·분류는 이후 단계로 명시한다.
5. 완성된 PRD는 `.docs/02_prd.md`로 저장한다.

## 5. 완료 기준

- 위 10개 섹션이 모두 구체적 내용으로 채워지고, 임의로 지어낸 값 없이 불명확한 부분은 "미해결 질문" 섹션에 명시된다.
- 사용자 답변(1인 사용자, 파일 업로드 고정, 조정 가능한 임계치 등)이 PRD 전반에 일관되게 반영된다.
- 문서는 한국어로 작성되고 `.docs/` 폴더에 번호 접두사 규칙에 따라 저장된다.
