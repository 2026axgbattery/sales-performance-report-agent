# MVP 계획서 — 영업실적·손익 분석 및 보고서 자동 생성 Agent

- 작성 대상: 국내영업본부 국내영업기획팀 김영우 책임
- 근거 문서: [.docs/02_prd.md](02_prd.md), [.docs/03_데이터정제.md](03_데이터정제.md), [.docs/04_기술스택.md](04_기술스택.md)
- 목적: PRD의 MVP(F1~F9 전체)를 실제로 어떤 순서·기준으로 만들지 정리한다.
- **변경 이력**: 최초에는 3일 PBL 기준으로 F1~F6만 MVP, F7~F9는 "v1.5"로 분리했으나, 실제 가용 개발 기간이 5일로 확인되어 F7~F9를 다시 MVP로 편입했다 (PRD 10장 미해결 질문 12번). v2(V1~V6, 인증·서버배포·웍스AI 고도화 등)는 여전히 이 계획서의 범위가 아니다.

---

## 1. MVP 범위 요약

MVP는 F1~F9 전체다 — "업로드 → 정제 → 증감률 계산 → 이상징후 플래그 → Overview 확인 → 이상징후 하이라이트 → 임계치 조정 → 보고서 초안 자동 생성 → 검토·수정 → 결과 다운로드"까지 전 과정을 포함한다.

| ID | 기능 | 한 줄 정의 |
|---|---|---|
| F1 | 파일 업로드 | 실적 파일(필수) + 판매계획·팀별손익계산서·제품분류 매핑표(선택) 업로드, 개수 제한 없음 |
| F2 | 데이터 정제·매핑 | 매핑표 조인("팀+제품코드" 키), 계정과목별 정제 규칙 적용 |
| F3 | 증감률·이상징후 계산 | 전월/전년/계획 대비 등 6개 기준으로 이상징후 판정 |
| F4 | Overview 화면 | 팀별 목표대비, 기간별 비교, 제품군별 분석, 팀×거래처 드릴다운, 요약 5개 영역 |
| F5 | 이상징후 하이라이트 | 임계치 초과 항목을 영향 금액순으로 정렬 |
| F6 | 임계치 설정 | 6개 판단 기준 임계치를 직접 조정·저장 |
| F7 | 보고서 초안 자동 생성 | 이상징후별 그래프 + 규칙/템플릿 기반 사실 서술 코멘트 |
| F8 | 보고서 초안 검토·수정 | 담당자가 코멘트 수정·삭제, 배경 설명 자유 텍스트 추가. 배경 설명 입력 시 사내 웍스AI가 F3 수치와 종합해 유추 문장을 생성 (PRD F8, 미해결 질문 15번 — 웍스AI 연동 세부사항은 아직 미확정) |
| F9 | 결과 다운로드 | Overview·이상징후 리스트는 엑셀, 상세 보고서 초안은 PDF·PPT 중 선택 다운로드 (PRD F9, 미해결 질문 4·16번 — PDF·PPT 실제 생성 방식은 아직 미확정) |

**명시적으로 제외되는 것** (PRD Non-goals 참고, v2로 유지)
- 다중 사용자 권한, 앱 내 이메일 발송 — **로드맵 전체에서 제외 확정** (NG1, NG3). 배포는 항상 담당자가 다운로드한 파일을 수동 공유하는 방식이다.
- SAP API 실시간 연동, 매핑표 자동 학습 (NG2, NG5)
- 회의체 발표용 PPT **디자인**(브랜드 템플릿·슬라이드 레이아웃 자동 편집) — F9의 기본 PPT export(그래프+코멘트를 슬라이드로 옮기는 수준)는 MVP에 포함하기로 범위가 조정됨 (NG4, v2 표 V1 참고)
- 사내 서버 상시 배포, 인증/SSO (NG6 — v2에서 담당자 접근 편의용으로만 추가, 경영진 등 타 이해관계자 직접 열람 목적 아님)
- 웍스AI 모델 API를 통한 자연어 코멘트 고도화 (v2 V6 — MVP의 F7은 규칙/템플릿 기반 코멘트만 사용)

## 4. 개발 순서 (5일 기준)

각 단계는 이전 단계가 로컬에서 정상 동작함을 확인한 뒤 다음 단계로 넘어간다.

### Day 1 — 데이터 파이프라인 기반 (F1 + F2)
- FastAPI 프로젝트 골격, DuckDB 스키마 생성 (UploadBatch~ProductMapping)
- 실적 파일(.xlsx/.xls/.csv) 업로드 API + 필수 컬럼 검증
- 제품분류 매핑표 업로드·파싱, "팀+제품코드" 합성 키 조인 로직 ([.docs/03_데이터정제.md](03_데이터정제.md) §3·§4.1 기준)
- 계정과목별 정제 규칙 구현 ([.docs/03_데이터정제.md](03_데이터정제.md) §4의 6개 패턴)
- **완료 기준**: 샘플 실적 파일 업로드 시 미매핑/계산오류 없이 정제 테이블이 DuckDB에 저장됨

### Day 2 — 계산 엔진 (F3 + F6)
- 6개 판단 기준(전월/전년/계획대비, 흑자→적자, 단가변동, 판관비급증) 계산 로직
- ThresholdConfig CRUD API + 기본값 시딩
- 이상징후 플래그 생성 로직, 임계치 변경 시 재계산 확인
- **완료 기준**: 임계치를 바꾸면 이상징후 플래그 결과가 즉시 바뀌는 것을 API 레벨에서 확인

### Day 3 — Overview·하이라이트 화면 (F4 + F5)
- Next.js 프로젝트 셋업 (shadcn/ui + design.md 토큰 매핑, Recharts)
- 업로드(F1) 화면 구현
- Overview(F4) 8개 섹션 — 실제 참고 양식 기준(PRD F4 참고): ①팀별 목표대비(수량·매출) ②팀별 목표대비(영업이익) ③전년동월대비 ④전년누계대비 ⑤전월대비 ⑥월별 실적분석(팀별, 12개월 트렌드) ⑦월별 실적분석(제품군별) ⑧팀×거래처별 상세, + 상단 요약 영역
- 이상징후 하이라이트(F5), 임계치 설정(F6) 화면
- **완료 기준**: F1~F6 전체 플로우가 로컬에서 오류 없이 동작 (이 시점에 원래의 "3일 MVP" 데모가 가능한 상태)

> F4가 5개 추상 영역에서 8개 구체 섹션으로 확장되어 Day 3의 프론트엔드 작업량이 커졌다. ⑥(12개월 트렌드)은 과거 UploadBatch가 누적되어 있어야 실제 데이터로 채워지므로, 데모용으로는 여러 달치 샘플 데이터를 미리 준비해 두어야 한다. 일정이 촉박하면 ⑥·⑦처럼 컬럼이 많은 섹션을 단순화하고 Day 5에 보완한다.

### Day 4 — 보고서 자동 생성 (F7)
- 이상징후 리스트 기반 그래프 데이터 생성 (Recharts)
- 이상징후 유형별 규칙/템플릿 코멘트 생성기 구현 (수치 기반 사실 서술 원칙 — 원인 추정 금지)
- ReportDraft·ReportItem 저장 로직
- 보고서 초안 화면 구현 ([output/f7-report-draft.html](../output/f7-report-draft.html) 참고)
- **완료 기준**: F5의 이상징후 리스트로 보고서 초안이 자동 생성되고, 코멘트가 실제 수치와 일치함

### Day 5 — 검토·다운로드 및 전체 통합 (F8 + F9)
- 보고서 초안 검토·수정 화면 (코멘트 수정/삭제, 배경 설명 추가, 항목 제외 토글) — [output/f8-report-review.html](../output/f8-report-review.html) 참고
- 결과 다운로드(Overview·이상징후 리스트·상세 보고서 엑셀) API 및 화면 — [output/f9-download.html](../output/f9-download.html) 참고
- 전체 플로우(F1→F9) 리허설, 엣지 케이스 재점검
- **완료 기준**: 아래 5장(Definition of Done) 전체 통과

> 일정은 권장안이며, 특정 단계가 지연되면 F4의 ③ 제품군별 분석(제품구분별 세부 비교)처럼 상대적으로 복잡한 하위 화면을 먼저 단순화하고 이후 보완하는 방식으로 조정한다. Day 3 종료 시점에 F1~F6까지는 별도로 데모 가능한 상태를 만들어 두면, 이후 일정이 밀리더라도 부분 데모가 가능하다.

## 5. MVP 완료 기준 (Definition of Done)

PRD 9장 "MVP 데모 성공 기준"과 동일하다.

- [ ] 실제(또는 샘플) SAP 실적 파일 1개월 치를 업로드하면 F1~F9 전체 플로우가 로컬 환경에서 오류 없이 동작한다.
- [ ] Overview(F4)의 8개 섹션과 이상징후 하이라이트(F5) 표시 수치가 실제 입력 데이터와 일치한다.
- [ ] 임계치 설정(F6)에서 값을 바꾸면 F3·F5 결과가 재계산·재표시된다.
- [ ] 보고서 초안(F7)의 코멘트가 수치 기반 사실 서술에 한정되고, 원인 추정을 포함하지 않는다.
- [ ] 검토·수정(F8)에서 담당자가 코멘트를 수정·삭제하거나 배경 설명을 추가할 수 있다.
- [ ] **F8에서 담당자가 배경 설명을 입력하면 사내 웍스AI 모델이 실제로 호출되어 F3 수치와 종합한 유추 문장이 생성된다** (사용자 확인 사항 — 목업 응답으로 대체한 상태는 이 항목을 충족한 것으로 보지 않으며, v2로 이월하지 않는다. [.docs/06_MVP_Todo리스트.md](06_MVP_Todo리스트.md) 상단 "MVP 완료 필수 게이트" 참고).
- [ ] 다운로드(F9)로 받은 파일(Overview·이상징후는 엑셀, 상세 보고서 초안은 PDF·PPT)이 기존 배포 경로(영업팀 공유/회의체/임원 메일)에 그대로 첨부 가능한 형태다.
- [ ] 수기 계산 대비 자동 계산 결과가 불일치 없이 일치한다 (수기 입력 오류 0건 목표).
- [ ] 매핑표에 없는 제품코드, 계산 오류, 전년 데이터 없음 등 8장의 엣지 케이스가 앱을 중단시키지 않고 화면에 표시된다.

## 6. 리스크 및 착수 전 확인 필요 사항

PRD 10장 미해결 질문 중 MVP 착수·진행에 직접 영향을 주는 항목만 정리한다 (전체 목록은 PRD 참고).

| 항목 | 영향 | 대응 |
|---|---|---|
| 판매계획·팀별손익계산서 파일의 실제 컬럼 스키마 미확보 (질문 2) | F1 검증 로직·F2 매핑 로직을 완성할 수 없음 | Day 1 착수 전 샘플 파일 확보 필요 |
| 임계치 기본값의 적정성 미검증 (질문 3) | F3 결과가 실제 업무 감각과 다를 수 있음 | 제안 기본값으로 우선 구현 후, 실 데이터로 조정(F6에서 즉시 대응 가능하므로 MVP 진행에는 지장 없음) |
| 동일 기간 재업로드 처리 정책 미확정 (질문 5) | F1 구현 시 임의로 "덮어쓰기"를 가정해야 함 | MVP는 단순 덮어쓰기로 구현, 실사용 전환 시 재검토 |
| ~~파일 종류 자동 인식 기준 미확정 (질문 6)~~ | F1 UI 설계에 영향 | **해결됨.** 자동 인식 로직 없이 항상 사용자가 직접 지정하는 방식으로 확정 (Day 1에 이미 이 방식으로 구현됨) |
| 제품코드 접두사 기반 예외 규칙(R/QZZ 외 추가 여부) 미확인 (질문 8) | F2 정제 결과의 정확도에 영향 | 확인된 규칙(R/QZZ→수량 0)만 우선 구현, 추가 발견 시 반영 |
| "지사"/"팀" 용어 불일치 (질문 9) | F1~F3 문서와 F4 요구사항의 그룹핑 축 표현이 다름 | MVP 구현은 실제 데이터 축인 "팀" 기준으로 통일해 진행 |
